# Python Track Element App 要件定義書

## 1. 業務要件

### システム概要

Spotifyのデータをハックし、ユーザー個人の「今の音楽成分」を可視化するとともに、独自のDJロジック（なだらかなEnergy上昇、年代ジャンプなど）に基づいた超パーソナルプレイリストを自動生成する、Webベースの選曲・プレイリスト生成アプリケーションを開発する。
ユーザーは、フロントエンドとバックエンドがPythonで完結しつつも、Web標準（HTML/CSS/htmx）の柔軟性を備えた画面を通じ、高度なデータ分析結果をクリーンなグラフで視覚的に楽しみながら、ワンクリックで本物のSpotifyアカウントへプレイリストを保存できる。

### 想定利用者

* 個人ユーザー（就活時の面接官・エンジニアへのアピール、および開発者自身の個人利用）

### ユースケース

#### 一般ユーザー

* アプリケーションにアクセスし、Spotifyアカウントでログイン（OAuth認可）する。
* 直近で聴いた50曲の「Danceability」「Energy」「Valence」などの音楽成分が可視化された画面を確認する。
* スライダーやボタンを用いて「フェードイン選曲」「タイムトラベル選曲」などの条件を選択し、自動選曲を実行する。
* 画面全体をリロードすることなく、非同期で提案されたプレイリストの楽曲一覧と、その成分遷移グラフを確認する。
* 「Spotifyに保存」ボタンを押し、自身のSpotifyアカウントに新しいプレイリストが自動生成されたことを確認する。
* API通信エラーやデータ不在時のエラーメッセージを、画面上の通知エリアで動的に確認する。

## 2. 機能要件

### アプリケーション種別

* Webアプリケーション（`FastHTML` を利用し、htmxによるコンポーネント単位の非同期UI制御と、Pico CSSによるセマンティックなWebレイアウトを構築）

### 機能一覧

#### Spotify API連携・データ取得機能

* `Spotipy` によるOAuth 2.0認可コードフローの実装（安全なアクセストークン取得）。
* ユーザーの「最近再生したトラック（直近50曲）」のメタデータ、およびオーディオ特徴量（Audio Features）の取得。
* アーティスト情報、および関連アーティスト（影響を受けた/似ている）の取得。

#### データ分析・DJ選曲ロジック（コア機能）

* **成分解析機能：** `TrackData(dataclass)` による楽曲データのカプセル化と、ユーザーの直近50曲のオーディオ特徴量の平均値算出。
* **フェードイン選曲（DJロジック）：** 1曲目の静かな曲から最後の激しい曲に向けて、Energyの数値をなだらかな右肩上がりに並び替えるロジック。
* **タイムトラベル選曲：** お気に入りアーティストを起点に、そのアーティストと類似性のある1970〜80年代の古い名曲をミックスするフィルタリングロジック。

#### GUI表示・可視化機能

* **Web標準のグラフ描画：** FastHTML画面上に「音楽成分レーダーチャート」および「選曲傾向の散図」を動的に埋め込み表示。
* **htmx駆動の操作コンポーネント：** 選曲ロジック切り替え用のラジオボタンや条件調整用スライダー。入力変更時にフォーム全体を再読み込みせず、結果表示領域のみを部分的に書き換える（`hx_post`、`hx_target` の活用）。
* **楽曲一覧表示：** 生成されたプレイリスト（タイトル・アーティスト・BPM等）を、Pico CSSのスタイルが適用されたセマンティックなHTMLテーブルで表示。
* **Spotifyプレイリスト書き出し：** 非同期通信で裏側の保存ロジックを安全に呼び出す「Spotifyに保存」サブミットボタン。

#### エラー処理・共通機能

* APIトークンの有効期限切れ、通信失敗、選曲候補データ不足時の例外処理。エラー時は画面をクラッシュさせず、エラー通知用のHTML断片（`cls="alert alert-danger"`）を動的にターゲット領域へ返却。
* **★試験対策の埋め込み（ロギング）：** 不要な文字列結合を避けるため、第一引数にフォーマット指定子（`%s`）を置き、第二引数以降に変数を渡す「遅延フォーマット評価」を徹底した `logging` の実装。Spotipy内部ロガーを保護する `disable_existing_loggers=False` の設定、および `dictConfig` による詳細なフィルター制御。
* **処理時間計測デコレータ：** API通信やPandasのソート処理にかかる時間を計測するカスタムデコレータの実装（`timeit` モジュールや `Timer.repeat()` の仕様を考慮）。FastHTMLのエンドポイント関数または内部ロジックに適用し、計測結果を画面にスマートに非同期出力する。

## 3. 非機能要件

### 開発環境

* Python 3.12
* python-fasthtml (Webフロントエンド・バックエンド構築)
* uv (パッケージ管理ツール。`uv.lock` による一貫した実行環境再現)
* VSCode
* GitHub / GitHub Actions (CIによる自動品質チェック：Ruff, Mypy, pytestの実行)

### 品質・保守性

* 全てのコードに型ヒントを付与し、`mypy`（厳格モード）による静的解析を通過させる。FastHTML特有のコンポーネントクラス（`Main`, `Div`, `FT_Component`等）の戻り値型アノテーションを明示し、外部デコレータには `[untyped-decorator]` の局所的抑制を行う。また `TypedDict` での `total=False`、`Self` 型、Python 3.12の `type` 文による型エイリアスを適用する。
* `Ruff` による自動フォーマットおよびリンター警告のゼロ化（`[tool.ruff.lint]` の `select` キーによる `isort(I)` 有効化、`quote-style` や `indent-style` のカスタマイズ適用）。
* `pytest` による単体テストの網羅（モデル、選曲ロジック、およびFastHTMLのテストクライアントを用いたエンドポイント検証）。`pytest.raises` を用いた例外（`TypeError`, `ValueError`, `MemoryError`）の発生とキャッチの検証。
* `unittest.mock` を用いた外部API（Spotify API）通信のモック化テスト（`autospec=True` や `spec_set` による属性へのゲット/セット制限、`unsafe=False` による assert タイポ防止、`assert_called_with` の引数検証）。

### セキュリティ要件

* APIの Client ID や Client Secret、アクセスキー等の秘匿情報は、環境変数（`.env`）で厳格に管理し、コード内や公開リポジトリへのハードコードを徹底的に排除する。
* **★試験対策の埋め込み（暗号化・セキュリティ）：** ユーザー識別子のハッシュ化（ストレッチング）処理において、`update()` の引数は `bytes-like` 必須で `str` 直渡しは `TypeError` になる仕様、`hexdigest()`（アンダースコアなし）は16進数文字列を返しSHA-256なら64文字になる仕様を満たすセキュリティロジックをリポジトリ層に実装する。
